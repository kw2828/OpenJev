# Decision after the proposal-memory comparison

**Close this proposal-memory configuration: the engineering support rule failed, 2/6.** Keep the original cold planner as the reference. No role beat both cold search and repeat-last by the required 3% over the complete episode. There was no scientific gate evaluation, and the result does not justify learned adaptation training.

## Evidence

All nine 200-action runs and their independent native replays completed. The three cold runs exactly reproduced the earlier native episodes and 9,600 saved decision arrays. The independent review authenticated the complete run membership and checked the 20 sources against their snapshots and the prospective commit `a9b689396207d62cd5285403296f05aa12744126`. The older 116-source and 136-source bindings remain intact.

Shifted-plan improvements against cold / repeat-last were **-12.38% / +5.78%** with nominal gain, **-0.30% / +1.94%** with known gain and the public observer, and **+4.72% / -2.26%** with known state and gain. Positive values mean lower native cost. None of the three pairs passes both fixed margins. Favorable intervals cannot replace the prospectively selected full episode.

The previous-plan representation is inexpensive in this implementation, but these results show no consistent control benefit. This is conventional proposal memory, not a trained recurrent world model, connectome advantage or new learning algorithm. The tested case is already exposed; it cannot become independent confirmation through more tuning.

## Next action

Prepare one separate, bounded **common-root planning-adequacy diagnostic**. Use a fixed set of already saved native states and compare the original search with additional search at the same horizon and a longer horizon at comparable native-transition cost. Score candidate sets from identical roots under declared objectives and current dynamics. This separates search and horizon effects from different closed-loop trajectories and public-observer errors.

The [follow-up design](followup-design.md) specifies the proposed contrasts and interpretation. It is not an executed result. Freeze its exact root set, source/input hashes, projection and extension rules, workload, runtime caps and stop conditions before any new native evaluations. Charge all cross-scoring and diagnostics to the work ledger. Do not tune or select roots after reading new outcomes.

If that diagnostic exposes a concrete planning limitation, test only the corresponding correction in a new engineering protocol. If it does not, stop this controller recipe and explicitly redesign the task/controller qualification instead of stacking more memory or biological components. Neither outcome automatically permits an architectural claim.

The four-fresh-case dynamics qualification remains unlaunched. Its current-gain and rolling-estimator thresholds, all closed study outcomes and all frozen sources remain unchanged. A learned recurrent or biological model still needs a task where useful hidden dynamics and meaningful conventional control improvements have first been demonstrated.
