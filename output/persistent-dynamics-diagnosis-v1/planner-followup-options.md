# A minimal stronger-planner comparison

Prospective design only. No simulator, planner, model or RNG call was made for this note. This is conditional on the separate saved-artifact diagnosis finding no implementation defect. It does not revise the negative engineering case, authorize a run or change the existing qualification thresholds.

**First compare trajectory-centered CEM256 against the current cold CEM256 and a repeat-last-action center, at the same H12/block3 objective and paid simulation budget.** This tests a conventional optimizer deficiency before asking a neural adapter to compensate for it. It adds no learned parameters, terminal value, hidden-gain input or future-goal preview.

## The specific missing mechanism

The current [search kernel](../../src/openjev/research/reacher_adaptive_search.py) initializes every decision around zero, retains seven constant anchors, scores four banks of 64, fits eight current-bank elites, and discards all proposal state after the decision. The [physics scorer](../../src/openjev/research/reacher_geometry_physics.py) then executes a separately scored first action from the same root. H12 sees 0.24 seconds; block3 provides only eight action coordinates. These are verified implementation properties, not a diagnosis of why the published case performed poorly.

The now-completed [saved candidate diagnosis](candidate-results-01/results.json), SHA-256 `e8d45fab596ea26b5dbee0f2b054551a411dec61dfbdc14b82b24651fe0e6618`, reports no score clipping and lower first-step prediction error for the exact-state reference despite worse control. In the first 50 actions, the selected zero-anchor fractions are 12% for nominal, 42% for public true gain and 32% for true state. Those observations make a search-adequacy check reasonable, but neither establish cold initialization as the cause nor rule out horizon/objective limitations.

Shifted proposal initialization is established MPC practice. [Pinneri et al., iCEM, arXiv:2008.06389v1, Sections 2.1 and 3.2-3.3](https://arxiv.org/html/2008.06389v1#S2.SS1) describe shifted Gaussian means, elite reuse, correlated samples and paid final-mean evaluation. Their results combine several changes and do not establish a benefit for this Reacher task. Our proposed single change is narrower and would not be an iCEM reproduction. [PlaNet](https://arxiv.org/pdf/1811.04551) is also a relevant precedent for iterative rollout planning without a terminal value; the absence of such a value alone is not proof of a defect. Neither source supports a novelty claim here.

## Three exact proposal variants

Keep the initial seven anchors, both original initial scales, all later CEM updates, final paid mean, earliest global-best tie rule, clipping, geometry/expected-action-cost score and terminal shortening unchanged. Change only the center of initial random slots 7 through 63:

| Variant | Initial center for each action block |
|---|---|
| `cold` | Zero, exactly the existing implementation. |
| `repeat_last` | Repeat the last actually issued command through the current planning horizon. |
| `shift_plan` | Shift the previously selected full action sequence by **one real action**, then project onto the current three-action blocks. |

At startup every center is zero. When the currently received public target differs from the preceding target, clear both non-cold centers before planning. That rule uses an observed change, not the scheduled event time or a future target. Do not clear memory on a hidden gain switch or feed it a change flag. Each role uses only its permitted current gain; all candidates are rescored under that current value even when it differs from the previous estimate.

For the previous-trajectory variant, let the last selected sequence be `U_prev` and the new actual horizon be `h=min(12,T-t)`. Remove its first action. If this leaves fewer than `h` actions, extend only the planning tail by repeating its last command. Otherwise take the first `h` remaining commands. This extension is an optimizer initialization, not a native action after episode termination.

The shifted sequence is generally no longer constant on new three-action blocks. Define each new block center as the float64 mean of its surviving commands, including the shorter final block. This is the least-squares projection onto the existing command family. It preserves block3 and the original number of optimized coordinates; it is **not** an exact shift of a block-aligned plan. Shifting one whole block instead would skip two unexecuted commands and test a different algorithm. Retain the unprojected tail and projected centers in the trace.

A narrow additive implementation can use the existing immutable `SearchInputs` interface: for initial slot `j` with fixed scale `s_j`, form `epsilon'_j = epsilon_j + center/s_j`, then pass it to the unchanged kernel, which evaluates `s_j*epsilon'_j` before clipping and float32 quantization. Anchors are still overwritten exactly as before. Specify this arithmetic order explicitly rather than claiming bitwise identity to a differently ordered `center+s_j*epsilon_j`. When all centers are zero, pass through the original inputs to guarantee exact parity. Retain the full original four-block shape, with zero centers in unused terminal-tail blocks. Preserve the base innovations and their identities separately from these derived inputs; the latter contain no new RNG draws.

Cache the previous selected sequence only after the real issued command is acknowledged. Reject skipped/duplicate decision boundaries and mismatched commands. A failed call is terminal for that attempt. No candidate's terminal state, score, model state or estimated gain is retained as if observed. A pure proposal-state wrapper can own this small buffer without changing the frozen search, physics model or observer. The new writer and independent auditor must bind the center derivation and base-to-derived innovation transformation; the old audit's common-input assertion cannot simply be bypassed.

## Matching and the first useful comparison

For every nonterminal root, every variant pays `256*min(12,T-t)` candidate transitions plus one selected-root advance, with exactly four 64-sequence scoring calls. Over T200 that is **597,504 candidate transitions and 200 selected advances per planned episode**. All duplicate, saturated and anchor proposals count. No old score or terminal state is reused. Root copies, center construction, retained buffer, geometry work, trace serialization and independent replay are additional measured costs; equal native-transition count is not equal wall time.

Pair the original full-horizon innovations, reset, target path and exogenous noise. Later trajectories and CEM banks may diverge. Targets and gains stay at their currently available values throughout each candidate rollout. Do not look ahead to the known event schedule, use a better dynamics model for one optimizer or let a candidate update an identifier.

The agreed bounded engineering matrix is the three proposal variants crossed with **public nominal**, **public state plus true current gain**, and **true state plus current gain**: nine 200-action episodes. Reuse the exact existing engineering seed410 case, targets, noise, gain path and saved base innovations from [control-engineering-01](../persistent-dynamics-qualification-v1/control-engineering-01/completed.json), with their hashes bound before execution. Keep its existing zero-command result only as a clearly inherited descriptive floor; a new zero row is unnecessary. The nine planned episodes pay 5,377,536 candidate transitions, 1,800 selected advances and 1,800 real actions. Cold-mode actions and native traces must reproduce the corresponding previous three rows exactly; wall times need not match. Keep rolling/frozen identification out of this first optimizer diagnostic. That separation asks whether the supplied-physics planner uses a fixed information set better before introducing online estimation error. It is not a substitute for the later six-role qualification.

Compare only the predeclared full/PRE/POST/MOVE native-cost windows in this nine-row matrix, separating distance and effort, plus exact cold-trajectory parity. A common-root counterfactual score comparison would require a separately specified follow-up; it is not part of this matrix's work or claims. Better imagined score without better native control would not establish planning adequacy. A gain only over cold search, matched by last-action centering, supports action persistence rather than a special benefit from retaining the full plan. A trajectory-centering failure stays visible. This comparison must not automatically select the best variant and reuse its cases as confirmation.

Before any numerical execution, freeze the three variants, boundary rules, case/source hashes, comparison arithmetic and finite caps. Audit all nine completed rows, including the derived-center history, every paid proposal, and selected-root replay. Keep this entire seed410 comparison as exposed engineering context and publish every row regardless of which looks better. Fresh-case qualification requires a separate decision and retains the original gain-utility and recovery criteria; this note adds no alternative pass route or automatic promotion based on the best engineering variant.

## Alternatives to defer rather than combine

**Deterministic local refinement:** a clean second optimizer comparator is the common initial 64-bank followed by twelve 16-proposal coordinate polls, totaling 256. At H12 there are eight block-action coordinates, so one poll evaluates positive and negative displacement on each coordinate from the incumbent. Fixed step lengths and incumbent/tie rules would need prospective declaration. Terminal shortening requires an explicit budget rule for inactive coordinates; duplicate paid proposals cannot be silently removed. This changes search allocation while retaining the objective, but uses 13 scoring calls instead of four and needs its own complete timing and replay accounting. It is an independently implemented pattern search, not a claim of iLQR or gradient-based MPC. It should not be stacked with warm starts in the first comparison.

**Terminal cost:** adding distance/velocity penalty or a learned value can address a different issue, but changes the scoring objective and introduces scale, equilibrium and training choices. An LQR-style terminal value is not automatically valid for the current clipped distance-plus-effort objective or throughout the nonlinear reaching region. It should wait for a separate explicit approximation/calibration design; no coefficient should be fitted to the unfavorable engineering trajectory.

**Longer horizon:** H24 at the same 256 proposals nearly doubles candidate transitions and doubles the block-coordinate dimension. H24 with 128 proposals matches `H*K` at interior roots only, changes search quality, and ceases to match work near terminal boundaries. A fair horizon experiment needs an explicit per-root transition ledger, matched shorter-horizon compute control and complete wall time. It is not the smallest test of the currently missing proposal reuse.

Warm starts are the recommended first change because they isolate an established, cheap optimizer mechanism while preserving the current objective, horizon, command family and native rollout budget. Even a positive result would establish only that a stronger conventional planner is needed before judging adaptation. It would not establish biological, recurrent-world-model or fast-weight novelty.
