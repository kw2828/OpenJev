# Fast adaptation after the error-gate screen

Source review, 19 September 2026. **Prospective research context, not a frozen experiment or a novelty claim.** Six primary papers were checked. No training, model inference, simulator call, scored random draw or current running-study outcome read was performed. Existing scientific sources were not changed.

**First qualify a tracking task where persistent actuator changes are both identifiable and costly to ignore. If it qualifies, the most concrete neural follow-up is a small, episode-local transition-weight adapter trained by real prediction error.** This is a stronger adaptation mechanism than changing a scalar memory gate, but online neural dynamics adaptation is already established. Its value would have to survive conventional identification and context-encoder controls.

The completed [error-gate development pilot](reacher-innovation-pilot.md) did not earn continuation. That does not justify searching architectures on its development outcomes. The earlier [Pendulum qualification](robotics-pendulum-qualification.md) is the more important design warning: gain was identifiable under excitation, yet a two-angle velocity estimate with nominal gain already controlled well, and little cost remained after the hidden switch. More latent parameters would not fix that missing control question. This note extends the [existing architecture options](reacher-architecture-mechanism-options.md) and [equation-level error-gate screen](../output/reacher-two-observation-control-v1/error-gated-mechanism-screen.md), without reopening either experiment.

## Qualify adaptation need before selecting a neural method

The current 50-action Reacher task has independent actuator noise. Past data cannot identify the next independent noise realization. Treating every surprise as changing physics risks adapting to noise instead of learning a useful persistent quantity.

A separate tracking qualification can change **one shared actuator gear gain**, while retaining fixed damping, command clipping, actuator-noise law and action-cost units. The task-design discussion proposes 200 actions, public goal changes every 50 actions, and an unannounced gain switch at 80 or 120. These are proposed qualification choices, not selected or frozen here. Gain changes must not coincide with a public goal-change announcement. Public goals should be issued independently of hidden gain and published before the associated action; specify whether future goal schedules are visible equally to every controller. Do not give a model a hidden change flag, actual noisy torque or simulator velocity.

Full visibility should come first. Missing-observation panels only become useful after identifying a control-relevant adaptation problem. The old static-target and 50-action validation contracts cannot be silently reused for this longer, changing-target task; it needs additive task and observer definitions.

Require both of these results from a separately frozen, supplied-physics qualification:

1. **Identifiability under legal inputs.** Excited public angle/command histories distinguish candidate gains at useful accuracy and latency; zero/weak excitation exposes ambiguity. For one scalar gain, a condition number is uninformative when it is trivially one: report sensitivity magnitude or scalar information, estimation uncertainty and actual gain error. Check saturation and the difference between issued commands and noisy applied control. Charge any prescribed probe actions to every episode's utility and use identical probes for paired methods.
2. **Control relevance.** Using the true gain improves tracking relative to nominal or stale gain with the *same public state observer*, planner and budget, particularly in a prespecified post-change window. Also retain a separately labeled true-state-plus-true-gain reference. This separates the value of parameter knowledge from privileged velocity. Report total native cost, post-change cost, tracking error and effort separately. A switch after effective stabilization, or a task robust to both gains, should stop the proposed neural comparison again.

The first practical identifier should fit a scalar gain to a short window of public angle transitions under supplied nominal dynamics. It should not use a regressor secretly constructed from true acceleration or actual actuator noise. A bounded grid or one-dimensional constrained least-squares fit is transparent; an EKF/RLS formulation is a further comparator only after deriving its legal measurement equation and acknowledging finite-difference/state-estimation error. Count all identification rollouts. If this controller already reaches the same-observer true-gain reference within a declared practical margin, a larger architecture study has little support on this task.

## One conditional implementation: prediction-trained transition fast weights

If a meaningful adaptation gap remains, build an **additive functional transition adapter**, not another reward- or variance-driven gate. A concrete small choice is a rank-four adapter of the GRU hidden-to-hidden transition matrix:

```text
W_eff(P) = W_hh + U4 Sigma4 P V4^T
P in R^(4x4), P_episode_start = 0
```

`U4, Sigma4, V4` are fixed factors computed from the offline-trained transition matrix. All backbone parameters and these factors stay frozen during deployment. `P` is episode-local state, not an in-place mutation of shared module weights. Its 16 coordinates alter the action-conditioned transition itself. Merely adapting the final angle decoder would not change the latent trajectory in the existing GRU: its next transition consumes hidden state, action and public metadata, not its predicted angles. An output-only adapter is consequently a useful conventional control, not an interchangeable implementation.

Use a short, fixed window of actual public packets and issued commands. At a real visible endpoint `t`, start from a saved, detached public-derived state at the window's left boundary and compute predictions under trial `P`. Minimize

```text
L_t(P) = mean over real observed endpoints j in the window
         ||public_angles_j - predicted_angles_j(P)||^2
         + lambda ||P||_F^2
P_new = project_radius(P_old - eta * clip_gradient(grad_P L_t(P_old)))
```

The initial engineering variant takes **one** fixed gradient update. Radius, step size, regularization, window and clipping are training-development choices, frozen before confirmation. No learned variance rescales this inner loss, and no reward supplies its target. This is an independently implementable first-order approximation to known online neural adaptation, not a reproduction of the cited second-order algorithm or a new delta rule. A damped small Gauss-Newton update on the *same* `P` is the stronger optimization comparator if update quality, rather than cost, becomes the bottleneck.

The causal sequence is important:

- Startup has a declared state and zero adapter, with no invented prior transition target. A missing packet provides no adaptation target and leaves `P` unchanged. A returned observation can supervise a multi-action rollout across its gap only using the stored left root and actual intervening commands. Do not use hidden angle placeholders or teacher-forced missing states.
- Treat each endpoint prediction as pre-assimilation. If a window includes intermediate visible packets, predict and score them before assimilating them. The current endpoint is assimilated once only after the update. Reconstruct the current state from the same saved left root under `P_new`, then assimilate the real endpoint. Charge this replay. The saved left state is an approximation tied to an earlier adapter; disclose this truncated-history approximation instead of calling it full-history refitting.
- Take a snapshot of the resulting root and adapter for planning. Every CEM candidate reads identical fixed `P_new`, with private fast hidden state. No candidate forecast trains `P`, updates an optimizer or contaminates another candidate. The selected first advance restarts at the real root. Only its eventual real observation can train the next adapter. This remains certainty-equivalent MPC, not dual control or stochastic optimal planning.

Offline training needs a separately declared dynamics-diverse corpus. The old iid-noise corpus alone supplies no evidence that an adapter can learn changing gain. Mean/reward supervision and any adaptation unroll must use observed public targets and known public metadata. True gain may generate the simulator and support evaluation diagnostics, but may not quietly become a model input or supervised target. A true-parameter teacher would be a separately labeled privileged-training arm. Initially avoid meta-learning: ordinary offline pretraining plus online adaptation is easier to audit. A later meta-trained initialization must pay for inner unrolls and higher-order gradients and be compared with the same non-meta adapter.

## Necessary comparisons and a falsifiable result

Keep the same training trajectories, paired initializations, observation information, planner proposals, geometry reward and adaptation opportunity. Later CEM proposal banks may differ because scores differ. Include:

- Frozen backbone (`P=0`) and the same backbone with the fixed-budget transition update above.
- Output-only last-layer adaptation, and an ordinary bounded-history context encoder conditioned into the transition. These test whether parameter plasticity matters beyond a generic correction or inferred context.
- Public-observer nominal gain, stale/frozen identified gain, and adaptive short-window scalar identification. Keep a same-observer true-gain reference separate from a true-state reference. A neural method receiving no nominal physics and a supplied-physics estimator have different prior knowledge; report that distinction rather than presenting them as information-identical learners.
- No-switch/nominal controls alongside both switch directions. A learned forgetting or reset rule must not receive the hidden switch time. An oracle reset can only be a labeled diagnostic.

The strongest narrow claim to test is: **real transition-error adaptation reduces post-change prediction and native tracking cost beyond fixed weights and amortized finite-history context, at measured deployment cost, while preserving no-change performance.** Require a practical gain across every retained fit and both switch directions under untouched cases; freeze the actual margins and stop rule only after task qualification. Report failure if better prediction does not improve control, scalar ID explains the gain, or online updates harm stationary conditions. Do not promote a mechanism on identification accuracy alone. Generalization to a different actuator change or a second environment would be a later confirmation, not part of the initial claim.

State/cost accounting must include `P`, fixed adapter factors, public replay buffers, root snapshots and copies, gradients, any optimizer moments and Jacobian/factorization scratch space. An RLS comparator additionally pays its covariance state and solves. Report adaptation attempts/completions, observed targets, replay steps, forward/backward calls, original observation/reward heads and analytic action-cost work, candidate rollout work, serialization, peak memory and complete controller wall time. Branch bookkeeping is part of actual cost, not an architectural advantage. Equal CEM256 or equal parameter count does not imply equal total compute.

**No justified architectural novelty emerges from this screen.** It supports a clear next qualification and an implementable adaptation comparator. A defensible later contribution would need a specific result that survives the close conventional explanations above, not a combination of fast weights, recurrence, uncertainty and biological terminology.
