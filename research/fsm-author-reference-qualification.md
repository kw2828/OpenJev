# FSM author-reference qualification

This is the historical source-only review. Subsequent registered studies produced
a [completed BLA28 reference](fsm-author-bla-results.md) and an
[incomplete NL-LFR diagnostic](fsm-author-nllfr-results.md). See also the separate
[publication correction](fsm-author-publication-correction.md).

**SOURCE REVIEW ONLY. No author control was fitted or executed.** No measurement arrays or supplied model weights were opened. Notebook source cells, repository metadata and primary papers were read; saved notebook outputs were not used. The proposed adaptation below is unregistered and unrun.

The authors provide executable BLA28 and neural NL-LFR recipes. The main remaining work is a restricted FIT reader, a pinned numerical environment and a qualified causal state initializer. Loading their pretrained models or running their notebooks unchanged would not establish a FIT-only comparison.

## Verified source facts

The dataset/notebook source is pinned to [`fsm-benchmark-data` commit 539a12fe](https://github.com/merijnfloren/fsm-benchmark-data/tree/539a12fef384b086a8562b500498b2fa3899ef70). Its README identifies the [baseline release v2026.04.15](https://doi.org/10.5281/zenodo.19591136). The independently inspected implementation is [`freq-statespace` commit a79e8c56](https://github.com/merijnfloren/freq-statespace/tree/a79e8c567b018a6c9462528fc1e10b77fd19b3e2), whose package version is 0.1.2. That later implementation pin is reproducible source identity, not proof of the exact environment that generated the supplied weights.

| Reference | Executable recipe and algorithm | Training scope in the supplied recipe |
|---|---|---|
| BLA28 | [`baseline_results/fit_BLA.ipynb`](https://github.com/merijnfloren/fsm-benchmark-data/blob/539a12fef384b086a8562b500498b2fa3899ef70/baseline_results/fit_BLA.ipynb): nonparametric frequency-response estimate, order-28 frequency-domain subspace identification, then BFGS refinement, `rtol=1e-3`, `atol=1e-5`, maximum 5,000 iterations. Uses 6,400 Hz sampling and excited frequency indices `arange(1,3840)`. | Separate 100, 200 or 300 mV models use the complete training tensor at that amplitude. The notebook defaults to 300 mV. |
| Neural NL-LFR | [`baseline_results/fit_NonlinearLFR.ipynb`](https://github.com/merijnfloren/fsm-benchmark-data/blob/539a12fef384b086a8562b500498b2fa3899ef70/baseline_results/fit_NonlinearLFR.ipynb): fit an unweighted pooled BLA28, connect a static 16-input/8-output ReLU network with two width-64 hidden layers, then BFGS for at most 10,000 iterations. Frequency weighting is explicitly disabled. | All training realizations at **100, 200 and 300 mV**, concatenated on the realization axis. This produces both an all-amplitude BLA and an NL-LFR. |

Thus even supplied `bla_100mV.zip` and `bla_200mV.zip` include our DEV realizations 3..5. The supplied all-amplitude models additionally include the intended 300 mV shift. These conclusions follow from the recipe and release description, not from inspecting the archives. The source writes `nllfr_all_data_amplitudes.zip`, whereas the repository inventory and analysis notebook use `nllfr_all_amplitudes.zip`; a reproduction must reconcile that filename explicitly.

The [2024 FSM paper, Sections 2.3 and 3.1](https://past.isma-isaac.be/downloads/isma2024/proceedings/Contribution_245_proceeding_3.pdf) specifies order 28, subspace dimension 29, and **1,000 Adam steps at 1e-4**, not the later BFGS recipe. It describes three orthogonal three-realization blocks per amplitude, two for training and one for testing, with the transient first period discarded. Reproducing the 2026 notebook must not be described as exact reproduction of that older optimizer recipe.

The NL-LFR equations are `x_next=A*x+Bu*u+Bw*w`, `y=Cy*x+Dyu*u+Dyw*w`, `z=Cz*x+Dzu*u`, `w=NN(z)`. The inspected implementation has no instantaneous `w -> z` algebraic loop. Its final nonlinear optimization updates the dynamic matrices and neural parameters jointly, while retaining normalization and the original BLA separately. This is a stronger model class than our frozen VARX plus residual. [`_model_structures.py`](https://github.com/merijnfloren/freq-statespace/blob/a79e8c567b018a6c9462528fc1e10b77fd19b3e2/src/freq_statespace/_model_structures.py), [`_nonlin_lfr.py`](https://github.com/merijnfloren/freq-statespace/blob/a79e8c567b018a6c9462528fc1e10b77fd19b3e2/src/freq_statespace/_nonlin_lfr.py).

The [2025 inference-and-learning paper](https://arxiv.org/html/2503.14409v2) explains periodic-data BLA initialization, latent-signal inference and subsequent full simulation refinement. Its intermediate estimator requires a nonlinearity linear in its parameters. The FSM neural notebook skips that intermediate stage and directly refines the randomly connected neural NL-LFR. These are related procedures, not interchangeable descriptions of the actual notebook.

## Dependencies, licenses and concrete gaps

- **Available implementation:** `create_data_object` and normalization are in `_data_manager.py`; subspace/BLA optimization in `_best_linear_approximation.py`, with vendored `dep/fsid.py`; nonlinear fitting in `_nonlin_lfr.py`; neural initialization in `static/_nonlin_funcs.py`; simulation and explicit `x0` support in `_model_structures.py`. The inspected neural constructor defaults to seed 42, and `connect` defaults to coupling scale `sigma=1e-4`. [`neural source`](https://github.com/merijnfloren/freq-statespace/blob/a79e8c567b018a6c9462528fc1e10b77fd19b3e2/src/freq_statespace/static/_nonlin_funcs.py).
- **Environment is not locked:** [`pyproject.toml`](https://github.com/merijnfloren/freq-statespace/blob/a79e8c567b018a6c9462528fc1e10b77fd19b3e2/pyproject.toml) specifies Python >=3.10, JAX >=0.4.38 excluding 0.7.0/0.7.1, Jaxtyping, Equinox, Optimistix, Optax and `nonlinear_benchmarks`. NumPy/SciPy are also used. There is no lockfile in the inspected tree. The notebooks do not set JAX x64 explicitly and describe an NVIDIA T600 runtime. Freeze package versions, precision, seed and device; CPU cost and convergence remain unmeasured here.
- **Separate licenses:** the [FSM license](https://github.com/merijnfloren/fsm-benchmark-data/blob/539a12fef384b086a8562b500498b2fa3899ef70/LICENSE) grants CC BY 4.0 for the dataset. [`freq-statespace/LICENSE`](https://github.com/merijnfloren/freq-statespace/blob/a79e8c567b018a6c9462528fc1e10b77fd19b3e2/LICENSE) is GPLv3-or-later; the vendored [FSID header](https://github.com/merijnfloren/freq-statespace/blob/a79e8c567b018a6c9462528fc1e10b77fd19b3e2/src/freq_statespace/dep/fsid.py) states GPLv3. Preserve attribution and applicable code-license notices. The dataset notice is not evidence of a separate permissive software license for every notebook.
- **FIT changes the estimator's information:** our first triplet at one amplitude gives one MIMO block, enough to estimate a frequency-response matrix but not between-block total variance. The inspected [BLA implementation](https://github.com/merijnfloren/freq-statespace/blob/a79e8c567b018a6c9462528fc1e10b77fd19b3e2/src/freq_statespace/_best_linear_approximation.py) detects unavailable variance and disables frequency weighting. Combining different amplitudes must not silently treat their systematic differences as repeated same-condition noise. The author pooled recipe already disables weighting.
- **Periodic scoring is not our request interface:** [`analyze_models.ipynb`](https://github.com/merijnfloren/fsm-benchmark-data/blob/539a12fef384b086a8562b500498b2fa3899ef70/baseline_results/analyze_models.ipynb) uses whole test signals and `simulate(...,offset=1000)`. The [extension helper](https://github.com/merijnfloren/freq-statespace/blob/a79e8c567b018a6c9462528fc1e10b77fd19b3e2/src/freq_statespace/_misc.py) prepends the signal's **last** samples. Applying that to a forecast request would let later inputs affect initialization. It is legitimate periodic simulation, but not a C100/H128 causal initializer. The published NRMSE also differs from our FIT-standardized error.

## Proposed executable FIT-only adaptation

1. Pin the sources above and an explicit CPU/float64 environment. Qualify source-only data access, axes, direct-feedthrough timing, serialization and causal initialization on fabricated systems before a numerical run. Do not call the notebooks' eager `FineSteeringMirror()` loader or load supplied weights.
2. Supply only 100/200 mV realizations 0..2, both complete periods, preserving each triplet and period axis. Pool amplitudes along the realization axis to `(8192,3,6,2)`. Let `create_data_object` compute channel normalization from those FIT values only. Its documented period averaging is an author-method preprocessing choice; evaluation must still retain and score each period separately. [`data preparation source`](https://github.com/merijnfloren/freq-statespace/blob/a79e8c567b018a6c9462528fc1e10b77fd19b3e2/src/freq_statespace/_data_manager.py).
3. Fit a pooled, explicitly **unweighted** BLA28 with subspace dimension 29, then the notebook neural NL-LFR initialized from that same fitted BLA. Preserve the BFGS tolerances and maximum iterations above, set seed 42 explicitly, and retain convergence/failure receipts. This is a FIT-restricted adaptation, not bitwise recovery of author weights. A runtime cap must be fixed before fitting; a capped incomplete fit is not an author-baseline result.
4. Add an explicit context-only `x0` estimator. For BLA28, solve the fixed observability least-squares problem using the available 99 paired samples `y[s+1:s+100]` and `u[s+1:s+100]`, then propagate to the first forecast state. This avoids inventing the unavailable initial `u[s]`. For NL-LFR, predeclare a bounded context-only state solve, with the BLA estimate as initialization, or another separately qualified initializer. Neither may read future outputs or use periodic tail warmup. Charge normalization, state inference, 128-step rollout and denormalization in complete-request timing.
5. Evaluate fixed models on the existing DEV windows with the same physical input alignment, normalization used for scoring, channel/record coverage and failure handling. Keep future 300 mV and official-test members closed. Report accuracy, all parameters/state, initialization work and runtime alongside longer VARX and folded affine controls. The missing causal initializer and unqualified environment are actionable implementation gaps, not missing public algorithms.

The original paper explicitly warns that amplitude-dependent resonance shifts may reflect input-delivery/measurement-campaign artifacts, not only plant nonlinearity. A later 300 mV result would therefore test robustness to that recorded scenario shift, not establish physical extrapolation, control performance or architectural novelty. No author-reference performance is claimed by this note.
